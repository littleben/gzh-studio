# 排版标准：组件都可以用，但要分散

这套标准来自一篇真实文章的四轮修改：
1. 第一版用力过猛；
2. 收着点之后又太朴素，「底色高亮没看到，标题也简单」；
3. 放开用组件后「有些地方稍微有点密集」；
4. 往回收一收，定稿。

结论只有一句：**每种组件都可以用，挑最合适的内容放，但不要连着堆。**

## 用量

| 元素 | 写法 | 全文建议 | `render.py` 超出会提示 |
|---|---|---|---|
| 红色/主色加粗 | `**…**` | 5～8 处，只给数字和结论 | > 10 |
| 下划线 | `++…++` | 4～6 处，每段最多 1 处 | > 8，或同一段 2 处 |
| 底色高亮 | `==…==` | 3～4 处，只给核心概念 | > 5 |
| 提示条 | `> [!TIP]` | 1～2 处 | > 2 |
| 居中金句 | `> 一句话` | 1～2 处 | > 2 |
| 引言卡 | `> [!INTRO]` | 开头 1 处 | |
| 本文看点 | `> [!TOC]` | 长文 1 处 | |
| 数据卡片 | `> [!DATA]` | 1～2 处 | |
| 时间线 / 胶囊列表 / 表格 | | 各 1 处，内容合适才用 | |
| 灰色旁注 / 踩坑提示 | `> [!NOTE]` `> [!WARN]` | 按需，它们很轻 | |

## 密度规则

1. **一屏最多一个容器组件。** 容器指卡片、表格、代码块、引用、提示条。两个容器之间至少隔一句正文。`render.py` 发现容器紧挨着会提示（图片、灰色旁注、踩坑提示不算）。
2. **列表项不要每条都加粗。** 6 条兜底方案做成 6 个胶囊，整屏都是主色，太密；这种情况改回普通列表，只给最重要的那一条加高亮。
3. **同一段里强调手段最多两种。** 加粗、下划线、高亮挤在一段里，就分不出重点。
4. **数字放一处就够了。** 正文里已经写了的数字，不要再做一遍数据卡片；数据卡片适合放在节首，接住小标题。
5. **口径说明用灰色旁注，不用黑框卡片。** 补充说明要轻，卡片留给主信息。
6. **章节开头不要连放两个组件。** 小标题下面先写一句话，再放组件。

## 交付前自查

- [ ] `render.py` / `publish.py --dry-run` 没有 WARN
- [ ] `preview.py --shots` 在 390 px 宽下看过每一屏，没有一屏全是主色
- [ ] 每张截图都裁到了正文说的那一块
- [ ] 标点用「」，不用英文引号和破折号
